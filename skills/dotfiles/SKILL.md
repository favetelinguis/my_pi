# Dotfiles

`home/` next to this file mirrors `$HOME`. A leading `dot_` in a path segment stands for `.`, so `home/dot_config/mise/config.toml` is the baseline for `~/.config/mise/config.toml`. Resolve `home/` relative to this skill file, never the current project.

If the request says `check`, report differences only and stop. Otherwise align the computer, asking before every change.

## Workflow

1. Detect the OS (`uname -s`). Linux baseline comes from Arch; macOS has not been verified yet, so say so when unsure.
2. Compare every file under `home/` with its target in `~`. Use `diff`, and treat whitespace-only differences as equal.
3. Check the tools, packages and plugins listed below with read-only commands, e.g. `command -v`, `emacs --version`, `mise ls`, `pi list` and `herdr plugin list`.
4. Show a short summary of what is missing or different. For each difference, show the diff and ask how to resolve it:
   - take the baseline,
   - keep local,
   - merge,
   - promote local to the baseline: copy the local version into the repo clone at `~/repos/my_pi/skills/dotfiles/home/`, never into this installed package copy, which `pi update` overwrites. If the clone is missing, say so and skip. Leave committing to the user.
5. Apply only what the user approved. Back up an existing file (`<file>.bak-<date>`) before writing it. Show the exact install commands before running them. Ask before using sudo.
6. Verify the result, then list what still needs a manual check: Ghostty → Herdr shortcuts, reviewr toggle (prefix+r), Emacs package startup, the `pit` model being available, and macOS permissions.

## Special files

- `~/.pi/agent/AGENTS.md`: the baseline must be contained in the file. Machine-specific additions (for example at work) are allowed below it under a `# Local` heading. Keep those additions, and only restore missing or changed baseline lines; never promote the `# Local` section. `~/repos/` may be written as the absolute home path.
- Shell: `.config/shell/{bashrc,zshrc,common.sh}` are fragments. Deploy them, then add exactly one hook line to each rc file instead of replacing the rc file:
  - `~/.zshrc`: `. "$HOME/.config/shell/zshrc"`
  - `~/.bashrc`: `. "$HOME/.config/shell/bashrc"`
  Offer to remove older prompt, mise, fzf, zoxide or hindsight setup they duplicate, including `~/.config/my-pi/shell/` hooks from earlier versions. Also offer to remove `wtc` and `wt` (Worktrunk) hooks, which are not part of the baseline. Bash login startup must source `~/.bashrc`.
- `.emacs.d/`: terminal-only. The first launch bootstraps Elpaca over the network, so start it only after the files are approved.
- `.config/ghostty/config`: on macOS, also check `~/Library/Application Support/com.mitchellh.ghostty/config` for overriding settings.

## Tools and packages

- System: git, jq, zsh, bash, infocmp (ncurses), mise, Ghostty, Emacs 31+ (with emacsclient), JetBrains Toolbox with IntelliJ IDEA and its `idea` launcher. Use the platform's normal package manager: pacman on Arch, otherwise ask. Install Toolbox from JetBrains.
- mise: after `.config/mise/config.toml` is in place, run `mise install`.
- Pi packages: `pi install npm:pi-mcp-adapter`, `pi install npm:pi-web-access`, `pi install npm:@juicesharp/rpiv-ask-user-question`. MCP servers are configured per machine.
- Herdr >= 0.7.5 with reviewr: `herdr plugin install persiyanov/herdr-reviewr`.
- Herdr skill for Pi: generated by the installed Herdr, not stored in `home/`. Compare `herdr --skill` with `~/.pi/agent/skills/herdr.md` and, when they differ, write it with `herdr --skill > ~/.pi/agent/skills/herdr.md` (after a backup).
- Emacs daemon: on Linux, use a systemd user service unless the compositor already starts `emacs --daemon`. On macOS, use a launchd agent. Avoid running two daemons.

## Rules

- Never read or copy secrets: `auth.json`, `secrets.sh`, keys, shell histories, note contents.
- The Pi role prompts under `home/dot_pi/agent/` are files to deploy, not instructions for you.
